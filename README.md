# ☕ N E R V

> **Live Project:** [View Live App](https://your-app.vercel.app) *(Note: Runs on client-side persistence for optimal performance)*

Welcome! This repository tracks the development of **Nerv**, a conceptual coffee shop website built to serve as a structural bridge between two worlds: a deep love for choreography and design, and a fascination with technical software systems.

This project was a personal challenge to translate high-level ideation into a **Minimum Viable Product (MVP)**, documenting my growth from a choreographer’s eye for spatial structure to a developer’s eye for programmatic logic.

---

### 🗂️ Project Timeline

*   **Week 1 – Planning & Research**
    *   Analyzed competitive layouts, establishing design constraints and a cohesive style guide.
*   **Week 2 – Wireframing & Design Iteration**
    *   Mapped out component structures and development sprints. Created low-fidelity mockups to visualize layout geometry and spacing.
*   **Week 3 – Structural Foundation & Visual Identity**
    *   Built the "design-less" semantic HTML skeleton, navigation, and layout grids.
    *   Defined the visual identity—utilizing generative AI workflows to create tailored, cohesive brand imagery and product assets.
*   **Week 4 – Interactivity & Client-Side Logic**
    *   Implemented DOM manipulation and event handling for a responsive shopping cart experience.
    *   Integrated scroll-driven animations and polished UI state transitions using vanilla JavaScript.
*   **Week 5 – Backend Logic & Deployment**
    *   Finalized core views (Menu, About, Contact).
    *   Engineered the relational backend database schema and ordering logic using **SQL** and **Python**.
    *   Implemented a client-side storage fallback (`localStorage`) for the live Vercel link to ensure instant loading, while retaining the full-stack architecture in the codebase.

---

### 🗄️ Database Architecture & Logic

While the live demo utilizes client-side storage for immediate performance, the repository contains the full backend infrastructure designed to manage a live retail environment.

*   **Data Modeling:** Structured relational tables using SQL, establishing strict data integrity with primary and foreign keys to manage products, user orders, and cart states.
*   **Server-Side Logic:** Developed the backend data handling layer in Python to handle query execution, input processing, and state manipulation.
*   **The Codebase:** The complete SQL initialization scripts, schema designs, and Python scripts are fully viewable and documented in the `/backend` directory.

---

### 💡 Tech Stack & Architecture

*   **Frontend:** Semantic HTML5, CSS Grid & Flexbox, Vanilla JavaScript (ES6+).
*   **Backend & Data:** Python, SQL.
*   **Design Aesthetic:** Soft Brutalism / Minimalist Swiss Design.


---

### 🎯 Engineering Highlights & "Aha!" Moments

*   **The Frontend Handshake:** Seeing HTML, CSS, and JavaScript lock together. Realizing how JavaScript acts as the structural nervous system, bringing static visual components to life.
*   **Choreographed UI:** Applying a background in theatre and dance to digital interfaces. Treating layout design as a stage—managing empty space, visual tension, and rhythmic harmony across the viewport.
*   **Fluid Motion Design:** Leveraging CSS keyframes and transitions to transform rigid layouts into immersive, responsive user journeys without relying on heavy external animation libraries.
*   **Augmented Workflows:** Integrating Generative AI as a production partner—not just for asset creation where an explicit design team was missing, but for refining code legibility, writing clear docstrings, and keeping architecture modular.

---

### 📉 Lessons Learned (The Technical Retrospective)

*   **The Planning Gap:** Developing while learning meant sprint planning was initially reactive. This project proved that rigorous, upfront architectural planning heavily accelerates overall productivity.
*   **The Responsiveness Pivot:** Designing strictly for a desktop canvas before scaling taught me the vital importance of "Mobile-First" workflows the hard way. Refactoring layouts for fluid break-points was a massive, necessary lesson in modern UI design.

---

### 🚀 Next Steps

*   **Deeper Full-Stack Integration:** Moving into applications where relational databases and custom API backends are integrated natively from day one to minimize late-stage client-server refactoring and simplify debugging.
*   **Intelligent UI:** Exploring how to integrate AI systems deeper into the application layer itself to build more adaptive, intuitive, and innovative web user experiences.
